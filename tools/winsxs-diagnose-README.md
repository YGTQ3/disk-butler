# 🔧 WinSxS / DISM 诊断工具

> 当 C盘管家的「清理 Windows 更新旧版本备份 (WinSxS)」**分析卡住、超时或报错**时，
> 用这个一键小工具采集定位证据。跑一次几分钟，生成一份**你可以逐行审查**的报告——
> **只读取系统状态，不删、不改、不联网，不收集任何个人文件。**

---

## 这是什么

两个文件（放同一个文件夹）：

| 文件 | 作用 |
|---|---|
| `winsxs-diagnose.bat` | 双击启动器，自动请求管理员权限 |
| `winsxs-diagnose.ps1` | 诊断本体（纯 PowerShell，每行代码都可审计） |

跑完在**桌面**生成一份 `disk-butler-winsxs-report.txt`，把它发回给开发者即可帮助定位问题。

## 为什么需要它

WinSxS 分析走的是微软官方 DISM 工具（`AnalyzeComponentStore`），**正常几分钟就完成**。
个别机器会卡很久甚至卡死，原因通常在系统侧——挂起的 Windows 更新、组件存储状态、
安全软件拦截、磁盘慢等。这些**光看现象猜不出来**，得看 DISM 自己的日志和当时的进程状态。
这个工具就是把这些关键证据一次性、自动地收集起来。

## 它会做什么 / 不做什么

| ✅ 会做 | ❌ 不会做 |
|---|---|
| 只读采集 8 项系统信息（见下） | 修改任何系统设置 |
| 运行一次**只读** DISM 分析（带 7 分钟硬超时） | 删除任何文件 |
| 把报告写到你的桌面 | 联网 / 上传任何数据 |
| —— | 收集个人文件、账号、聊天记录、用户名 |

> 报告发不发**完全由你决定**；发送前建议先用记事本打开自己看一遍。

## 怎么用（三步）

1. 把 `winsxs-diagnose.bat` 和 `winsxs-diagnose.ps1` 放到**同一个文件夹**；
2. **双击 `winsxs-diagnose.bat`** → 弹出 UAC 授权窗口点「是」→ 按提示按回车开始；
   - 需要管理员权限，是因为要读系统日志、看系统进程、跑 DISM 分析；启动器会自动帮你请求，只弹一次。
3. 等几分钟（**最多 7 分钟会自动结束**，不会一直卡着）；完成后桌面生成
   `disk-butler-winsxs-report.txt`，先看一眼，愿意的话发到 **ygtq1021@126.com**，
   主题写「C盘管家·WinSxS/DISM 诊断报告」。

> 为什么双击 `.bat` 而不是 `.ps1`？因为 Windows 默认双击 `.ps1` 是用记事本打开、不会运行。

## 报告里有什么（8 节）

| 节 | 采集内容 | 用来判断 |
|---|---|---|
| 1/8 | 系统版本、内存、处理器、C 盘空间、磁盘类型(SSD/HDD)与健康 | 慢盘/坏盘/盘满会拖慢 DISM |
| 2/8 | 挂起更新 / 待重启标志、最近安装的更新 | 是否「有待重启的更新锁住组件存储」 |
| 3/8 | 关键服务状态（TrustedInstaller 等） | DISM 依赖的服务是否被禁用 |
| 4/8 | 已安装的安全/杀毒软件 + Defender 状态 | 是否安全软件拦截系统文件访问 |
| **5/8** | **只读 DISM 分析交叉验证（核心）**：带 7 分钟硬超时跑一次同款分析，期间每 10 秒采样 TiWorker/Dism 的 CPU/IO | 到底是「真在跑只是慢」还是「卡死不动」 |
| 6/8 | DISM 日志尾部（`dism.log` 最后 80 行） | 最权威的「卡在哪一步」证据 |
| 7/8 | CBS 日志尾部（`CBS.log` 最后 60 行） | 组件存储 / servicing 细节 |
| 8/8 | 最近 7 天系统事件日志（Servicing / WindowsUpdate 相关错误警告） | 补充时间线 |

## 安全吗

安全。全程只读；核心的第 5 节跑的是微软官方**只读**分析命令 `AnalyzeComponentStore`
（与 C盘管家用的是同一条命令，只分析、不更改系统），并且带 7 分钟硬超时——
**若超时，脚本会自动结束这次只读分析**（只读操作，中断不会损坏系统），
这正好也复现并记录了「卡住」这个现象本身。

---

## 🛠 维护者视角：拿到报告怎么定位根因

按下面顺序看，基本能锁定方向：

1. **先看 [5/8] 的采样行**——这是「慢 vs 死锁」的分水岭：
   - `TiWorker`/`Dism` 的**区间 CPU / 区间 IO 长期为 0** → **死锁/等待**（不是真在算），
     多因挂起更新、组件存储损坏、安全软件拦截；
   - **区间 CPU/IO 持续非 0** → **真在跑只是极慢**，多因磁盘慢或组件存储巨大；
   - 结果是「超时(>420s)仍在运行」= 复现了用户反馈的卡死；「N 秒内完成，退出码 X」= 这次没卡，看退出码。
2. **看 [6/8] `dism.log` 尾部**——DISM 会把卡点/拒绝访问/损坏写在这里，最权威。
3. **看 [2/8] 挂起更新标志**——`RebootPending`/`RebootRequired`/`pending.xml` 有任一为真 →
   优先建议用户「重启装完更新再重试」。
4. **看 [3/8] TrustedInstaller**——被禁用(`Disabled`/`Stopped` 且起不来) → DISM 无法工作，指导改「手动」并启动。
5. **看 [4/8] 安全软件**——有第三方杀软/EDR → 建议临时退出后重试（对应「退出码 5 拒绝访问」同源问题）。
6. **看 [1/8] 磁盘类型/健康 + [8/8] 事件日志**——机械盘/盘满/盘坏 + Servicing 报错，解释「慢」和「整机卡顿」。
