# 安全排查与漏洞修复 SOP（给 AI 与人类贡献者）

> 本文档是可执行规范：**遇到安全问题时逐条照做，无需自行发挥**。
> 适用范围：`disk-butler/src-tauri/`（Rust 后端）+ `src/`（前端）+ `capabilities/` + `tauri.conf.json`。
> 最高原则：**宁可多报一个"理论风险"，不可放过一个真提权路径。拿不准 = 当作风险登记，不静默略过。**
> 配套记录（证据/档案，不在本仓库、在工作区 `docs/`）：漏洞档 `docs/17-*`、审计报告 `docs/18-*`、待办 `docs/07`、索引 `docs/00`。

---

## 0. 何时触发本 SOP

命中任一即启动安全排查：
1. 新增/改动**提权入口**（`Start-Process -Verb RunAs`、`runas`、以管理员执行任何东西）；
2. 新增/改动**删除逻辑**（`Remove-Item`、`std::fs::remove*`、清理残留/孤儿）；
3. 新增/改动**IPC**（命名管道、服务、跨进程通信）；
4. 把**外部可控输入**（注册表值、前端参数、文件路径、软件名）拼进命令行 / 脚本 / SQL；
5. 用户反馈疑似漏洞，或例行的阶段性全量审计。

## 1. 审计七维度（逐项过，不可跳）

| # | 维度 | 重点看什么 |
|---|---|---|
| 1 | 不安全临时文件 / TOCTOU | 向 `temp_dir()`/固定可预测路径写文件后再执行/提权/读取；`.ps1/.bat/.vbs/.log` 落地 |
| 2 | 提权执行 / UAC | 被执行内容来源是否可信、能否被同账户篡改；exe 是否在仅管理员可写目录 |
| 3 | 命令注入 / 脚本注入 | 拼接进 PowerShell/cmd/`format!` 的输入；引号转义是否充分（换行、`$()`、反引号、`%var%`）|
| 4 | 路径遍历 / 任意删除 | 白名单/安全根校验能否被 `..`、符号链接、大小写、前端回传绕过 |
| 5 | Tauri command 暴露面 | 接收前端参数并触发删除/提权/执行的 command，参数是否**后端重新校验**而非信任前端 |
| 6 | 命名管道 / 服务 IPC | SDDL/DACL 是否最小授权；是否校验请求来源、拒远程、限长度 |
| 7 | 其它 | 硬编码密钥/凭据、不安全反序列化、日志泄露敏感信息 |

## 2. 分级标准（每条发现都要打级 + 写触发前提）

| 级别 | 判据 |
|---|---|
| 🔴 Critical / P0 | 可直接利用、能提权或造成数据丢失；**公开发版前必须修** |
| 🟠 High | 需较弱前提即可利用，或影响面大 |
| 🟡 Medium | 需前提（如"前端已被 XSS/篡改""本机已被入侵"）才能利用，属纵深防御 |
| 🟢 Low | 影响有限（如仅伪造展示文字）、不提权、不丢数据 |

> 诚实原则：**必须写清"触发前提"**（是不是远程？要不要本机已沦陷？），不夸大也不淡化。

## 3. 信任边界红线（写代码/审代码都守）

1. **不信任前端直传路径**：涉及提权/删除/停进程的入口，一律后端按 `id` 重读目标（`install_loc_of(id)`、`UninstallString` 等），前端只传 `id`。（反例见 docs/18 · V1）
2. **提权脚本不落地**：要提权执行的脚本用 `-EncodedCommand`（UTF-16LE+Base64）内联进命令行，`%TEMP%` 不落 `.ps1`/`.bat`；命令需交给 cmd 解析时经**环境变量**传递，避免落地文件被篡改（TOCTOU）与 PowerShell 传参破坏引号。（正例见 `bloatware.rs::run_elevated_ps`/`run_cmd_block`）
3. **单引号转义**：拼进 PowerShell **单引号字符串**的外部值一律 `s.replace('\'', "''")`；且必须确认它落在单引号语境内。
4. **删除走"当场重扫白名单 + `canonicalize` 校验"**：前端回传的待删路径必须命中后端当场重扫的允许集合，且过安全根校验（`canonicalize` 化解 `..`/符号链接、`starts_with` 安装根、非根本身）。
5. **IPC 最小授权**：管道/服务只授予完成功能所必需的权限（如只给"启动+查询"不给"停止/改配置"）；校验指令白名单、拒远程、限请求长度。

## 4. 建档与修复留痕（四层同步，缺一不可）

> 目的：**多会话协作下，让后续"功能开发"会话一眼知道改了什么、为什么、还剩什么**。

1. **代码内溯源注释**：每处安全改动加注释指向报告条目，如 `// 安全（docs/18 · V1）：...`；
2. **漏洞档 `docs/17-*`**：一个漏洞一份档，含概述/位置/攻击路径/风险边界/修复方案/验收/修复记录；次级发现附排查表；
3. **独立审计报告 `docs/18-*`**：范围+七维度+漏洞清单（分级 + 触发前提 + 建议 + 状态列 ✅已修复/⏳待评估/已复核可接受）+ 复核安全项；
4. **待办 `docs/07`**（恢复上下文先读）：登记已修/待评估项 + 给功能开发的信任边界提醒；新建报告在 `docs/00` 索引登记。

## 5. 修复验收（勾完才算"已修复·待验证"）

- [ ] 漏洞点已按红线消除，且**同类入口全部同步**（改一处别漏其它调用方）；
- [ ] `cargo test --lib` 全绿；涉及编码/转义的加**单测**（如 base64 向量、UTF-16 编码）；
- [ ] 前端契约同步（command 签名改了，`invoke` 调用也改）；
- [ ] 真机验证关键路径（正常成功 + 取消 UAC 正确报错 + 中文/空格路径）；
- [ ] 四层留痕完成（见第 4 节）。

## 6. 披露纪律（对外）

- **未修复的漏洞不公开**：细节只留在工作区 `docs/17/18`（离线档案），不写进对外文案、README、Release Notes、知乎等；
- 修复并发版后，如需对外说明，只讲"已加固/已修复"的结论，不给可复现的攻击步骤；
- 涉及第三方软件的问题按事实中性陈述，不定性、不点名攻击。
