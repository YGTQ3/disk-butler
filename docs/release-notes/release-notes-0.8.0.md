# v0.8.0 发布说明（2026-09-30）

## 主题
「DISM 体验版」＋ 磁盘透视准确度大修。

## 本版本改动

### 1. 磁盘透视准确度大修（PR#11，感谢上游库作者 [@kikijiki](https://github.com/kikijiki)）
MFT 直读引擎依赖 `ntfs-reader` 从 0.4.5 升级到 0.5.3，删掉 831 行手写 MFT 底层代码、改用库 0.5 新 API（合并提交 `4f615bf`，squash）。**本版核心价值是修复旧引擎一处长期容量漏报；扫描速度为次要、温和的改善**。

- **C 盘容量漏报修复（本版核心）**：旧引擎把 `$DATA` 排在扩展记录（`$ATTRIBUTE_LIST`）里的大文件算成 0 字节，导致 C 盘已用容量被系统性低估。同一台真机、同款 rayon 并行引擎、管理员权限各连测 5 次取平均：

  | 口径 | 旧 0.4.5 | 新 0.5.3 | 系统实际已用 |
  |---|---|---|---|
  | C 盘已识别容量 | 169.6 GB | **185.6 GB** | 189.9 GB |
  | 与实际偏差 | −10.7%（少算约 20 GB） | **−2.3%**（正常，差值为主动排除的回收站/系统元文件） | 基准 |

- **硬链接计数修正**：从误把 DOS 8.3 短名别名当硬链接，修正为只数真硬链接（本机文件总数新旧基本一致，约 76.1 万；容量差异来自大文件不再被算成 0，而非文件数变化）。
- **扫描速度（次要）**：C 盘全盘 MFT 扫描 5 次平均 **1.89s → 1.52s**（稳定态约 1.68s → 1.47s，快约 13%~20%）。
  > 数据澄清：透视引擎**本就是秒级**——真正「数十秒 → 秒级」的跨越来自 0.7.0 用 MFT 直读替代逐目录遍历（jwalk，快约 33×），并非本次升级。0.4.5→0.5.3 的速度增益温和，主要价值在准确度。（早期文档曾引用 `29.88s→4.48s`，那是**单线程对比原型工具 `mftscan`** 的口径，并非用户实际使用的并行引擎，现已废弃该说法、改用上表真机并行引擎实测值。）

### 2. DISM / WinSxS 清理体验（「DISM 体验版」主体）
「清理 Windows 更新旧版本备份 (WinSxS)」从"黑框干等、不知道死没死"改为"跑时可见、卡住会提示、文案诚实"：
- **已用时心跳**：分析 / 清理进行中实时显示「已用时 X 分 XX 秒」，不再只有一个静态估计干瞪眼。
- **诚实文案**：把「约 1~3 分钟」「约 5~20 分钟」这类硬承诺改为「通常…慢时更久」，数据诚实、不夸大。
- **卡住软阈值提示**：分析超 5 分钟、清理超 25 分钟时给出安心提示——分析是只读的、可放心重启重试；清理则明确劝「请勿关机、别强行中断」（途中断电有损坏组件存储的风险）。提示复用现有告警框样式，不另起视觉。
- （后端两道防呆——挂起更新预检 `update_pending` ＋ 退出码人话翻译 `dism_exit_hint`——已于 v0.7.10 上线，本版补齐前端体验。）

### 3. 诊断工具改进
`winsxs-diagnose` 只读分析硬超时 300 → 420 秒（7 分钟），慢机器不再被过早误判「卡死」；配套 README 判读口径同步。

### 4. 修复：高级清理“同意授权却报已取消”
修复「系统临时文件清理」（及 DISM 分析/清理）在用户**已同意 UAC 授权**后仍误报「已取消授权、未执行清理」。根因是提权退出码 `1` 被语义重载——「用户取消 UAC」与「提权脚本执行返回 1」（如停/启 Windows 更新服务 `wuauserv` 的附带错误）都返回 1，旧代码武断地把所有 1 当成「取消」。现引入专用取消码 `1223`（Win32 `ERROR_CANCELLED`）：外层 `try/catch` 精确捕获 UAC 取消才报「已取消」，脚本执行的真实退出码如实透传；系统清理 inner 脚本加 `exit 0` 兜底（清理「尽力而为」，释放量以清理前后空闲差计，不被服务操作附带错误污染）。四个提权入口一并修复。
