# 功能开发基准（DEV-STANDARDS）· 功能开发会话每次照此执行

> 目的：规范开发、减少发散性思考带来的错误。本文件是「功能开发」领域的作业清单；跨会话协作见根目录 `AGENTS.md`，UI 细则见 `docs/ui-reference/README.md`。
> 用法：开发任何 disk-butler 功能前扫一遍「设计基准」，收工前逐条对「开发纪律」自检。

## 一、设计基准（做成什么样）
1. **产品红线**（不可逾越）：不恐吓、不越权删、宁漏报不误报、用户自决、不联网上传、无常驻进程。
2. **高危操作两步式**：凡涉及删除/提权/停服务，必须「先只读分析给出预计释放量/影响 → 看清 → 再红色确认执行」，不允许"一个按钮直接干"。
3. **用户数据永不当垃圾**：含用户文档/笔记/项目的目录（如 pcsuite/Youdao）只识别+说明，永不进"可清理"。判不准归属的一律不列。
4. **未定稿大类功能默认隐藏**：靠编译期环境变量门控（如 `DISKBUTLER_FEATURE_BLOATWARE`），不设即隐藏、且不进公开包；前端入口 + 后端命令注册由同一开关管。发布功能（如孤儿残留搬进一键清理）不得被误门控。
5. **UI 一致性**：高级清理类功能一律沿用 `docs/ui-reference/README.md` 的范式——主页面内联（不用弹窗做主流程）、状态机 `idle→intro→分析→结果面板→confirm→running→done`、左明细(数字加粗更黑)+右绿色底面板(预计释放大字+按钮在框内)、三弹窗(引导/确认/完成)。新功能照抄，不另起炉灶。
6. **文案大白话**：去术语、说"这是什么/删了会怎样"，危险分级用红色，数据诚实（真实实测数字，不夸大）。

## 二、开发纪律（怎么做才不出错）
1. **先探查再动手**：改任何现有代码前，先用 Search 子智能体/Read 摸清结构与调用点，别凭印象改（教训：门控时误关孤儿命令、系统级路径想当然）。
2. **改前再 Read、用 SearchReplace 外科改**：不整文件覆盖；`original_text` 要够唯一，`new_text` 必须与旧文不同（别写成 no-op）；匹配失败不硬改，重 Read 看现状（多半是别的会话已改）。
3. **后端信任边界**：提权/删除/停进程入口，后端一律按 id 重读目标路径，不信任前端直传。
4. **清理必记账**：任何释放空间的路径后端调 `stats::record(&app, freed)`，前端清完 `loadStats()`，并入历史累计。
5. **验证全绿才算完**：`cargo test`（`CARGO_INCREMENTAL=0`）+ `npx tsc --noEmit` 双绿；改了门控要同时验 feature ON / OFF 两种形态。
6. **独立复核用子智能体**（呼应 AGENTS §5/§8）：发版前、高风险改动后，起 CodeReview 子智能体从实际 diff 独立审红线（入口是否隐藏、信任边界、有无夹带他会话改动、有无遗漏收尾），主会话据其清单修复——不自己裁判自己。
7. **隔离提交**：`git status`/`git diff` 看清来源，只提交本任务文件；commit 遵 `type(scope): 描述`（scope 用 dev）；绝不把其他会话未完成改动一起提。
8. **临时文件收尾**：诊断/中间文件用完即删、别落盘根；提权脚本用 `-EncodedCommand` 内联，不落可被篡改的 %TEMP% 脚本。
9. **实证验证铁律**：清理规则入知识库前，须真机"造出→实删→确认软件照常"；提权执行路径若沙箱内 UAC 弹不出，须交用户在 dev 里冒烟测试后才算过。
10. **采集器三入口同步**：采集逻辑有三份并行实现（主程序内置版 / 独立 exe 版 `tools/collector` / PowerShell 版），**任何探测规则的增改必须三处同步改**，缺一处会导致不同入口产出的样本报告口径不一致。改采集/探测逻辑时先确认自己覆盖了全部三处。
11. **完工即回写跟踪文档**（教训：`deep_clean_system` v0.7.4 已落地但 docs/07 想法池未标注完成，导致后续会话误判为未开工）：任何功能/修复一旦合入代码，**当场**执行：① docs/07 对应条目标注 ✅已完成（或删除并指向 docs/08）；② 属里程碑则追加 docs/08 大事记；③ docs/19 看板销坑。不允许“先做下一个、回头再整理”——回写是完工的一部分，不是额外动作。

## 三、发版前检查表（功能开发会话，正式发版必过）
- [ ] 未定稿功能入口已隐藏（不设门控 env = 默认隐藏）；
- [ ] `cargo test` + `tsc` 双绿；
- [ ] CodeReview 子智能体审过 diff、问题已修；
- [ ] 版本号三处一致（package.json / tauri.conf.json / Cargo.toml）；
- [ ] NSIS 产物重命名：`Copy-Item "target\release\bundle\nsis\C盘管家_${version}_x64-setup.exe" "DiskButler_${version}_x64-setup.exe"`（GitHub 上传不支持中文文件名；⚠ Tauri2 无 `installerName` 配置字段，勿再臆造——build 产物名由 productName 决定，中文名靠此步改名）；
- [ ] 提交已隔离、只含本次目标；
- [ ] docs/07 待办 / docs/08 大事记 / docs/19 看板已同步。
